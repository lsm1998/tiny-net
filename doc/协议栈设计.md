# tiny-net 自定义协议栈

## 一、项目概述

tiny-net 是一个基于 C 语言（C99）实现的用户态网络协议栈，覆盖从链路层到 Socket API 的完整链路。底层通过 libpcap 收发原始以太网帧，与宿主机网络共存，当前代码支持 Ethernet、ARP、IPv4、ICMP、Raw Socket、UDP、TCP、DNS 和 Loopback。

**核心架构特点：**

- **事件驱动**：消息队列解耦收发与协议处理
- **多线程模型**：PCAP 收/发线程 + 消息处理线程
- **预分配内存**：固定内存块池，避免动态 malloc
- **分层设计**：每层协议独立实现，通过回调注册组合

## 二、实现步骤

### 步骤 1：基础设施层

搭建协议栈运行所需的底层数据结构和工具模块。

#### 1.1 双向链表 (nlist)

> 文件: `nlist.h` / `nlist.c`

侵入式双向链表，将 `nlist_node_t` 嵌入到宿主结构体中，通过 `nlist_entry()` 宏从节点指针反推宿主结构体指针。

**关键接口：**

| 接口 | 说明 |
|---|---|
| `nlist_init()` | 初始化空链表 |
| `nlist_insert_first/last()` | 头插/尾插 |
| `nlist_remove()` | 删除节点 |
| `nlist_for_each()` | 遍历宏 |

#### 1.2 内存块分配器 (mblock)

> 文件: `mblock.h` / `mblock.c`

预分配固定大小的内存块池，用链表串联空闲块。支持信号量阻塞等待，线程安全。用于 pktbuf、netif、socket 等对象的分配。

**关键接口：**

| 接口 | 说明 |
|---|---|
| `mblock_init(mem, blk_size, count, lock_type)` | 初始化内存池 |
| `mblock_alloc(timeout_ms)` | 分配（可阻塞） |
| `mblock_free(block)` | 释放（唤醒等待者） |

#### 1.3 定长队列 (fixq)

> 文件: `fixq.h` / `fixq.c`

基于环形数组的定长 FIFO 队列，读写两端各有信号量，支持阻塞入队/出队。用于网卡收发队列、消息队列。

**关键接口：**

| 接口 | 说明 |
|---|---|
| `fixq_init(size, share_type)` | 初始化队列 |
| `fixq_send(msg, timeout_ms)` | 入队 |
| `fixq_recv(timeout_ms)` | 出队 |

#### 1.4 线程同步 (nlocker)

> 文件: `nlocker.h` / `nlocker.c`

轻量锁抽象，支持 `NONE`（无锁）和 `THREAD`（互斥锁）两种模式。

**关键接口：** `nlocker_init(type)` / `nlocker_lock()` / `nlocker_unlock()`

#### 1.5 工具函数 (tool)

> 文件: `tool.h` / `tool.c`

字节序转换（`htons`/`ntohs`/`htonl`/`ntohl`）、16 位校验和计算等。

#### 1.6 调试模块 (dbug / dbug_module)

> 文件: `dbug.h/.c`, `dbug_module.h/.c`

按模块开关的分级日志系统（info/warn/error），支持运行时启用/禁用单个模块的输出。

**模块列表：** `PKTBUF`, `NETIF`, `EXMSG`, `TIMER`, `ETHER`, `ARP`, `IPV4`, `ICMP`, `RAW`, `UDP`, `SOCKET`, `SOCK`, `PLATFORM`, `APP`, `COMMON`

### 步骤 2：数据包缓冲区 (pktbuf)

> 文件: `pktbuf.h` / `pktbuf.c`

**设计思路：** 将网络数据包表示为多个固定大小块（`pktblk_t`）的链表，每块 128 字节，按需自动串联，避免大块连续内存分配。

**关键数据结构：**

```
pktblk_t:
  ├── payload[128]            固定缓冲区
  ├── data                    指向 payload 中有效数据的起始位置
  ├── size                    当前块中的有效数据长度
  └── node                    链表节点

pktbuf_t:
  ├── total_size              所有块数据总长度
  ├── blk_list                块链表
  ├── ref_count               引用计数
  └── pos / curr_blk / blk_offset  读写游标
```

**关键接口：**

| 接口 | 说明 |
|---|---|
| `pktbuf_alloc(size)` | 分配指定大小的包缓冲区（自动链多个块） |
| `pktbuf_free(buf)` | 释放（引用计数为 0 时回收） |
| `pktbuf_add_header(size)` | 在头部预留空间（用于封装协议头） |
| `pktbuf_remove_header(size)` | 剥离头部（用于解析协议头） |
| `pktbuf_write/read/peek()` | 数据读写 |
| `pktbuf_seek(offset)` | 定位游标 |
| `pktbuf_set_cont(size)` | 确保头部连续（便于直接转型为协议头指针） |
| `pktbuf_checksum16()` | 计算 16 位校验和 |
| `join_pktbuf(dst, src)` | 合并两个 pktbuf |

**配置参数：**

| 参数 | 值 | 说明 |
|---|---|---|
| `PKTBUF_PAYLOAD_SIZE` | 128 | 单块大小 |
| `PKTBUF_BLK_COUNT` | 100 | 总块数 |
| `PKTBUF_BUF_COUNT` | 100 | 总缓冲区数 |

### 步骤 3：平台抽象层 (plat)

> 文件: `sys_plat.h/.c`, `net_plat.h/.c`

隔离操作系统差异，提供统一的线程、信号量、互斥锁、内存/字符串操作接口。

**支持平台：**

| 平台 | 实现 |
|---|---|
| Linux / macOS | pthread + POSIX 信号量（自定义条件变量封装） |
| Windows | Win32 API (`CreateThread`, `CreateEvent`, `CreateMutex`) |

**类型抽象：**

- `sys_thread_t` — 线程
- `sys_sem_t` — 信号量
- `sys_mutex_t` — 互斥锁
- `net_time_t` — 时间类型

**当前代码中的网络配置方式：**

- 宿主机网络接口信息通过 `pcap_get_first_netif()` 动态获取
- tiny-net 虚拟 IP 根据宿主机 IP 自动推导
- 规则是把最后一个字节设置为 `95`，如果宿主机本身就是 `*.95`，则改为 `*.96`
- 默认虚拟 MAC 为 `12:34:56:78:9A:BC`

### 步骤 4：PCAP 网卡驱动

> 文件: `netif_pcap.h` / `netif_pcap.c`

通过 libpcap 桥接协议栈与物理网络，实现虚拟网卡驱动。

**工作流程：**

1. `netif_pcap_open()`：根据 IP 查找 pcap 设备，打开混杂模式抓包
2. 创建两个后台线程：
   - **recv_thread**：`pcap_next_ex()` 读帧 → pktbuf 封装 → `netif_put_in()` 入队
   - **send_thread**：`netif_get_out()` 出队 → pktbuf 提取 → `pcap_inject()` 发送

**数据结构：**

```c
typedef struct pcap_data_t {
    const char* ipaddr;     // 宿主机真实网卡 IP（用于匹配 pcap 设备）
    const uint8_t* hwaddr;  // 虚拟 MAC 地址
} pcap_data_t;
```

> 说明：当前实现里，pcap 设备是通过宿主机真实网卡 IP 匹配出来的；tiny-net 自己对外提供的逻辑 IP 会在 `netif_set_addr()` 时单独配置成虚拟 IP。

### 步骤 6：消息系统 (exmsg)

> 文件: `exmsg.h` / `exmsg.c`

协议栈的核心调度器。所有网络事件和 Socket 操作都封装为消息，投递到统一的消息队列，由单一消息处理线程串行处理，避免多线程竞态。

**消息类型：**

| 类型 | 说明 |
|---|---|
| `NET_EXMSG_TYPE_NETIF_IN` | 网卡收到数据包 |
| `NET_EXMSG_TYPE_FUNC` | Socket API 调用请求 |

**工作流程：**

- **收包路径**：`recv_thread` → `netif_put_in()` → `exmsg_netif_in()` → 消息线程处理
- **Socket 路径**：`x_sendto()` → 封装 `func_msg_t` → `exmsg_func_exec()` → 消息线程执行 → 信号量通知调用方完成

**关键数据结构：**

- `exmsg_t`：消息包装（类型 + 关联接口/函数指针）
- `func_msg_t`：函数调用请求（回调 + 参数 + 完成信号量 + 错误码）

### 步骤 10：ARP 协议

> 文件: `arp.h` / `arp.c`

实现 IP 地址到 MAC 地址的映射，维护 ARP 缓存表。

**ARP 报文格式（28 字节）：**

```
硬件类型(2) + 协议类型(2) + 硬件长度(1) + 协议长度(1) + 操作码(2)
+ 发送方 MAC(6) + 发送方 IP(4) + 目标 MAC(6) + 目标 IP(4)
```

**缓存状态机：**

```
FREE (空闲)
  └→ 创建条目 → WAITING (等待应答)
                  ├→ 超时重试（最多 5 次，每次 5 秒）→ 失败丢弃
                  └→ 收到应答 → RESOLVE (已解析，120 秒老化)
                                  └→ 超时 → FREE
```

**关键接口：**

| 接口 | 说明 |
|---|---|
| `arp_init()` | 初始化缓存表（50 条目），启动 1 秒周期定时器 |
| `arp_resolve(netif, ip, buf)` | 解析 IP→MAC，未命中则发 ARP 请求并缓存包 |
| `arp_in(netif, buf)` | 处理收到的 ARP 请求/应答 |
| `arp_make_request()` | 广播 ARP Who-has |
| `arp_make_reply()` | 回复 ARP 请求 |
| `arp_find(ip)` | 查表 |

**配置参数：**

| 参数 | 值 | 说明 |
|---|---|---|
| `ARP_CACHE_SIZE` | 50 | 缓存条目数 |
| `ARP_MAX_PKT_WAITING` | 5 | 每条目最大等待包数 |
| `ARP_TIMER_TMO` | 1s | 扫描周期 |
| `ARP_ENTRY_STABLE_TMO` | 120s | 稳定条目超时 |
| `ARP_ENTRY_PENDING_TMO` | 5s | 等待条目超时 |
| `ARP_MAX_RETRY_COUNT` | 5 | 最大重试次数 |

### 步骤 11：IPv4 协议 — 网络层

> 文件: `ipv4.h` / `ipv4.c`

**IP 头格式（20+ 字节）：**

```
版本(4b) + 首部长度(4b) + 服务类型(8b) + 总长度(16b)
+ 标识(16b) + 标志(3b) + 片偏移(13b) + TTL(8b)
+ 协议(8b) + 首部校验和(16b) + 源 IP(32b) + 目的 IP(32b)
```

#### 11.1 路由表

- **数据结构**：`route_entry_t`（网络地址, 掩码, 下一跳, 接口, 掩码位数）
- **路由查找**：最长前缀匹配（比较掩码位数）
- **最大条目**：32

#### 11.2 IP 分片与重组

- **发送**：超过 MTU 的包按 8 字节对齐拆分，设置 MF 标志和片偏移
- **接收**：按 (源IP, 标识) 收集分片，完整后合并
- **配置**：`IPV4_FRAGS_MAX_NR` = 5（并发重组数），超时 5 秒

**关键接口：**

| 接口 | 说明 |
|---|---|
| `ipv4_init()` | 初始化路由表和分片缓冲 |
| `ipv4_input(netif, buf)` | 收包：校验→路由→重组→按协议分发 |
| `ipv4_output(proto, dst, src, buf)` | 发包：封头→校验和→路由→ARP→分片→发送 |
| `find_route_entry(ip)` | 最长前缀匹配路由查找 |
| `route_entry_add/remove()` | 路由增删 |

**协议分发：**

| 协议号 | 处理函数 |
|---|---|
| 1 (ICMP) | `icmp_v4_input()` |
| 6 (TCP) | `tcp_input()` |
| 17 (UDP) | `udp_input()` |
| 其他 | `raw_input()` |

### 步骤 12：ICMP 协议

> 文件: `icmp_v4.h` / `icmp_v4.c`

**ICMP 头格式（8+ 字节）：**

```
类型(8b) + 代码(8b) + 校验和(16b) + 标识/序号或保留(32b) + 数据
```

**支持的类型：**

| 类型 | 说明 |
|---|---|
| 0 | Echo Reply（回显应答） |
| 3 | Destination Unreachable（目的不可达） |
| 8 | Echo Request（回显请求） |
| 11 | Time Exceeded（TTL 超时） |

**关键接口：**

| 接口 | 说明 |
|---|---|
| `icmp_v4_init()` | 初始化 |
| `icmp_v4_input()` | 收包处理：校验→Echo Request 自动回复→其他转 raw socket |
| `icmp_v4_output_unreach()` | 发送目的不可达报文 |

**Echo 处理流程：** 收到 Echo Request → 交换源/目的 IP → 类型改为 Reply → 重算校验和 → 发送

| `x_socket(domain, type, protocol)` | 创建 socket (`AF_INET`, `SOCK_RAW`/`SOCK_DGRAM`/`SOCK_STREAM`) |
| `x_bind(fd, addr, len)` | 绑定地址 |
| `x_listen(fd, backlog)` | TCP 监听 |
| `x_accept(fd, addr, len)` | TCP 接收连接 |
| `x_connect(fd, addr, len)` | 主动连接 |
| `x_send(fd, buf, len, flags)` | 面向连接发送 |
| `x_recv(fd, buf, len, flags)` | 面向连接接收 |
| `x_sendto(fd, buf, len, flags, addr, len)` | 发送 |
| `x_recvfrom(fd, buf, len, flags, addr, len)` | 接收 |
| `x_setsockopt(fd, level, opt, val, len)` | 设置选项 |
| `x_getaddrinfo()` / `x_freeaddrinfo()` | DNS 解析接口 |
| `x_close(fd)` | 关闭 |

**兼容层（`net_api.h`）：** 通过宏将标准 `socket`/`bind`/`sendto`/`recvfrom` 等映射到 `x_` 前缀接口，使应用代码可以直接使用标准 POSIX socket 写法。

**文件描述符管理：**

- 全局 FD 表，最多 64 个（`SOCKET_MAX_FD`）
- socket 创建时分配 FD，close 时回收

**常量定义：**

```c
AF_INET = 2, SOCK_STREAM = 1, SOCK_DGRAM = 2, SOCK_RAW = 3
IPPROTO_ICMP = 1, IPPROTO_UDP = 17, IPPROTO_TCP = 6
SOL_SOCKET = 0, SO_RCVTIMEO = 1, SO_SNDTIMEO = 2
SO_KEEPALIVE = 8, SO_NONBLOCK = 9
TCP_KEEPIDLE = 4, TCP_KEEPINTVL = 5, TCP_KEEPCNT = 6
```

### 步骤 16.1：TCP 协议

> 文件: `tcp.h` / `tcp.c` / `tcp_in.c` / `tcp_out.c` / `tcp_state.c`

当前代码已经实现 TCP，而不是函数桩。主要能力包括:

- 被动打开

- 发送与接收缓冲
- FIN/RST 状态流转

- `TCP_RECV_BUF_SIZE = 4096`

### 步骤 16.2：DNS

> 文件: `dns.h` / `dns.c`

当前代码包含最小可用的 DNS 查询实现:

- 若输入本身是 IPv4 字符串，则直接返回
- `localhost` 直接解析为 `127.0.0.1`
- 其他情况通过内部 UDP socket 查询默认 DNS 服务器 `8.8.8.8`

DNS 模块包含:

- 缓存表
- 请求表
- 超时重试定时器

但它更偏“够用的最小实现”，不是完整 libc 级解析器。

## 四、收包流程

```
物理网络
  ↓
PCAP recv_thread
  ↓  pcap_next_ex() 读取原始以太网帧
  ↓  pktbuf_alloc() + pktbuf_write() 封装到 pktbuf
  ↓  netif_put_in() 放入接口输入队列
  ↓  exmsg_netif_in() 发送消息通知
  ↓
消息处理线程
  ↓  从 netif->in_q 取出数据包
  ↓  调用 link_layer->input() (以太网层)
  ↓
ether_input()
  ├→ 0x0806 (ARP) → arp_in() → 更新缓存 / 回复请求
  └→ 0x0800 (IPv4) → ipv4_input()
                       ├→ 校验 IP 头
                       ├→ 处理分片重组
                       └→ 按协议号分发:
                            1  → icmp_v4_input() → Echo 自动回复
                            6  → tcp_input() → TCP 状态机
                            17 → UDP 接收队列 → 唤醒 recvfrom()
                            *  → raw_input() → 分发到 raw socket
```

---

## 五、发包流程

```
应用层
  ↓  x_send/x_sendto(fd, data, size, ...)
  ↓
Socket API → exmsg_func_exec() → 消息线程
  ↓  sock->ops->send()/sendto()
  ↓
UDP/TCP/Raw 输出路径
  ↓  分配 pktbuf，写入用户数据，封装协议头
  ↓  ipv4_output(protocol, dest_ip, src_ip, buf)
  ↓
IPv4 输出
  ├→ 封装 IP 头，计算校验和
  ├→ find_route_entry() 查路由
  ├→ 超过 MTU 则分片
  └→ arp_resolve() 解析下一跳 MAC
       ├→ 缓存命中 → 直接发送
       └→ 缓存未命中 → 发 ARP 请求，数据包排队等待
  ↓
ether_raw_out()
  ↓  封装以太网头（目的 MAC + 源 MAC + 0x0800）
  ↓  netif_put_out() 放入接口输出队列
  ↓
PCAP send_thread
  ↓  netif_get_out() 取出数据包
  ↓  pcap_inject() 发送到物理网络
```

## 六、线程模型

| 线程 | 职责 |
|---|---|
| 主线程 | 初始化协议栈后进入 sleep 循环 |
| 消息处理线程 | 串行处理所有网络事件和 Socket 操作（无竞态） |
| PCAP 收线程 | 持续从 pcap 读帧，放入接口输入队列（每接口一个） |
| PCAP 发线程 | 持续从接口输出队列取帧，`pcap_inject` 发送（每接口一个） |

**同步机制：**

- `fixq` 的信号量实现队列阻塞
- `func_msg_t` 的信号量实现 Socket API 同步等待
- `mblock` 的信号量实现内存分配等待
