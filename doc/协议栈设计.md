# tiny-net 协议栈设计

## 1. 项目定位

`tiny-net` 是一个基于 C99 的用户态 IPv4 协议栈。它通过 `libpcap` 直接收发以太网帧，在宿主机网络之上提供一套自实现的网络协议与 Socket API。

当前代码已经覆盖：

- 链路层：Ethernet、ARP、Loopback
- 网络层：IPv4、ICMPv4、路由表、分片/重组
- 传输层：Raw Socket、UDP、TCP
- 名称解析：最小可用 DNS 客户端
- 用户接口：BSD 风格 `socket`/`bind`/`connect`/`send`/`recv`
- IO 复用：`select`、`epoll`

当前不支持：

- IPv6
- DHCP
- IP 转发 / NAT
- TLS/SSL
- 组播
- 动态路由协议

## 2. 实际入口与启动路径

当前应用和示例统一使用 [`src/app/common/common.c`](/Users/liushiming/CLionProjects/tiny-net/src/app/common/common.c) 里的 `tiny_net_init()` 作为真实入口，而不是 [`src/net/src/net.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/net.c) 的 `net_init()/net_start()`。

这是当前代码里最需要澄清的一点：

- `tiny_net_init()` 是完整启动路径，示例程序都走它
- `net_init()/net_start()` 只初始化了部分模块，暂时不是主流程

`tiny_net_init()` 的实际顺序如下：

```text
main()
  -> tiny_net_init()
     -> pktbuf_init()
     -> exmsg_init()
     -> netif_init()
     -> net_timer_init()
     -> arp_init()
     -> ipv4_init()
     -> ether_init()
     -> socket_init()
     -> raw_init()
     -> upd_init()
     -> dns_init()
     -> tcp_init()
     -> loop_init()
     -> netdev_init()
          -> pcap_get_first_netif()
          -> 生成虚拟 IP
          -> netif_open("vnet0", &netdev_ops, ...)
          -> netif_set_addr()
          -> netif_set_hwaddr()
          -> netif_set_active()
          -> netif_set_default()
     -> exmsg_start()
```

## 3. 总体架构

协议栈可以分成 5 层：

1. 平台与驱动层  
   `sys_plat.*`、`net_plat.*`、`netif_pcap.*`

2. 基础设施层  
   `nlist`、`mblock`、`fixq`、`pktbuf`、`timer`、`dbug`

3. 核心控制层  
   `netif`、`exmsg`、`ipv4 route table`

4. 协议实现层  
   `ether`、`arp`、`ipv4`、`icmp_v4`、`raw`、`udp`、`tcp`、`dns`

5. 应用接口层  
   `socket`、`net_api`、`select`、`epoll`

一个简化的运行图如下：

```text
应用线程
  -> x_socket/x_send/x_recv/x_getaddrinfo
  -> exmsg_func_exec()
  -> exmsg 工作线程
  -> 协议栈内部处理

pcap recv_thread
  -> netif_put_in()
  -> exmsg_netif_in()
  -> exmsg 工作线程
  -> ether/arp/ipv4/udp/tcp...

pcap send_thread
  <- netif->out_q
  <- ether_raw_out()/netif_out()
```

### 4.3 定长队列 `fixq`

[`src/net/net/fixq.h`](/Users/liushiming/CLionProjects/tiny-net/src/net/net/fixq.h) / [`src/net/src/fixq.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/fixq.c)

`fixq` 是带信号量阻塞能力的环形队列，主要用在：

- `exmsg` 消息队列
- `netif` 输入队列
- `netif` 输出队列

### 4.4 包缓冲 `pktbuf`

[`src/net/net/pktbuf.h`](/Users/liushiming/CLionProjects/tiny-net/src/net/net/pktbuf.h) / [`src/net/src/pktbuf.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/pktbuf.c)

`pktbuf` 是整套协议栈的中心数据结构。它用多个固定大小的数据块拼接一个逻辑数据包，而不是要求整包连续内存。

当前关键特征：

- 单块大小：`PKTBUF_PAYLOAD_SIZE = 128`
- 块数量：`PKTBUF_BLK_COUNT = 100`
- `pktbuf` 数量：`PKTBUF_BUF_COUNT = 100`
- 支持头部扩展、头部裁剪、游标访问、跨块读写、校验和
- 支持 `pktbuf_set_cont()`，在需要直接访问协议头时临时整理成连续区域

这也是协议栈能够方便做：

- 逐层封装 / 解封装
- IP 分片重组
- ARP 未解析时缓存待发包

### 4.5 定时器 `timer`

[`src/net/net/timer.h`](/Users/liushiming/CLionProjects/tiny-net/src/net/net/timer.h) / [`src/net/src/timer.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/timer.c)

定时器不是独立线程驱动，而是由 `exmsg` 工作线程在消息循环里顺带推进：

- `net_timer_first_mo()` 决定 `fixq_recv()` 的等待时间
- `net_timer_check_mo()` 负责扣减超时并触发回调

当前使用它的模块主要有：

- ARP 老化和重试
- DNS TTL 与重试
- TCP keepalive / TIME_WAIT 等连接定时器

### 4.6 调试系统 `dbug`

[`src/net/net/dbug_module.h`](/Users/liushiming/CLionProjects/tiny-net/src/net/net/dbug_module.h)

## 5. 平台层与网卡驱动

### 5.1 平台抽象

[`src/plat/sys_plat.c`](/Users/liushiming/CLionProjects/tiny-net/src/plat/sys_plat.c)

平台抽象统一了：

- 线程
- 信号量
- 互斥锁
- 时间
- sleep
- 基础内存 / 字符串接口

当前代码保留了多平台分支：

- `SYS_PLAT_WINDOWS`
- `SYS_PLAT_LINUX`
- 一套早期嵌入式 / 教学平台分支

在本仓库默认构建下，主目标是 Linux/macOS + `pthread` + `libpcap`。

### 5.2 pcap 驱动

[`src/plat/netif_pcap.c`](/Users/liushiming/CLionProjects/tiny-net/src/plat/netif_pcap.c)

`netif_pcap` 是真实外网入口。`netdev_init()` 会：

1. 调用 `pcap_get_first_netif()` 获取宿主机网卡信息
2. 生成 tiny-net 虚拟 IP
3. 打开 `vnet0`
4. 启动两个后台线程

线程职责如下：

- `recv_thread`
  - `pcap_next_ex()` 抓包
  - 封装成 `pktbuf`
  - 投递到 `netif->in_q`

- `send_thread`
  - 从 `netif->out_q` 取包
  - 拷贝到线性缓冲区
  - `pcap_inject()` 发到物理网络

### 5.3 虚拟地址策略

当前默认策略来自 [`src/app/common/common.c`](/Users/liushiming/CLionProjects/tiny-net/src/app/common/common.c)：

- 读取宿主机 `IP / Netmask / Gateway`
- tiny-net 虚拟 IP 取同网段地址，最后一个字节优先用 `95`
- 如果宿主机本身就是 `*.95`，则改用 `*.96`
- 默认虚拟 MAC：`12:34:56:78:9A:BC`

这意味着当前工程更偏“单机实验网络协议栈”，不是通用自动配置方案。

## 6. 网络接口、消息与路由

### 6.1 `netif`

[`src/net/net/netif.h`](/Users/liushiming/CLionProjects/tiny-net/src/net/net/netif.h) / [`src/net/src/netif.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/netif.c)

`netif_t` 表示一个网络接口，当前支持：

- `NETIF_TYPE_ETHERNET`
- `NETIF_TYPE_LOOPBACK`
- `NETIF_TYPE_WIFI`（类型枚举存在，但无独立实现）

关键能力：

- 维护接口状态：`CLOSED -> OPENED -> ACTIVE`
- 维护 IP / Netmask / Gateway / MAC / MTU
- 维护输入输出队列
- 按接口类型绑定链路层处理器

激活接口时的实际行为：

- 非 loopback 接口首次激活会自动成为默认接口
- 自动插入直连路由
- 设置默认接口后，如果网关有效，会插入默认路由
- 以太网接口会触发免费 ARP

### 6.2 `exmsg`

[`src/net/net/exmsg.h`](/Users/liushiming/CLionProjects/tiny-net/src/net/net/exmsg.h) / [`src/net/src/exmsg.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/exmsg.c)

`exmsg` 是当前架构的核心串行化层。协议栈并没有让多个线程直接并发操作 TCP/UDP/ARP 表，而是让它们经由统一消息线程进入。

当前消息类型只有两类：

- `NET_EXMSG_TYPE_NETIF_IN`
- `NET_EXMSG_TYPE_FUNC`

分别对应：

- 网卡收到包，通知协议栈处理
- 应用线程发起一个 Socket/DNS 请求，请工作线程执行

`EXMSG_QUEUE_SIZE = 10`，所以它是一个比较小的控制队列，不适合堆积大量长时间任务。

### 6.3 路由表

路由实现位于 [`src/net/src/ipv4.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/ipv4.c)，由 `route_entry_t` 维护。

当前特征：

- 最大路由项：`IPV4_ROUTE_TABLE_MAX_NR = 32`
- 查找策略：最长前缀匹配
- 来源：
  - 接口激活时自动添加直连路由
  - `netif_set_default()` 添加默认路由

当前没有：

- 动态路由更新
- 转发表
- 三层转发

## 7. 协议实现

### 7.1 Ethernet

[`src/net/src/ether.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/ether.c)

职责：

- 为 `NETIF_TYPE_ETHERNET` 注册链路层处理器
- 收包时解析以太网头
- 把 `0x0806` 分发给 ARP
- 把 `0x0800` 分发给 IPv4
- 发包时补以太网头

实现细节：

- 如果目标 MAC 就是本接口 MAC，`ether_raw_out()` 不走 pcap，直接回送到本接口输入队列
- 发送 IPv4 数据前会先通过 ARP 找 MAC

### 7.2 ARP

[`src/net/net/arp.h`](/Users/liushiming/CLionProjects/tiny-net/src/net/net/arp.h) / [`src/net/src/arp.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/arp.c)

ARP 缓存是协议栈的重要状态表。

当前参数：

| 参数 | 值 |
|---|---|
| `ARP_CACHE_SIZE` | 50 |
| `ARP_MAX_PKT_WAITING` | 5 |
| `ARP_TIMER_TMO` | 1 秒 |
| `ARP_ENTRY_STABLE_TMO` | 120 秒 |
| `ARP_ENTRY_PENDING_TMO` | 5 秒 |
| `ARP_MAX_RETRY_COUNT` | 5 |

行为特征：

- 缓存命中：直接返回 MAC
- 缓存未命中：创建 `WAITING` 项，发送 ARP 请求，挂起待发包
- 收到应答：转 `RESOLVE`，把等待链表里的包全部发出去
- 周期老化：超时后重试或回收

此外，收 IPv4 包时会从源 IP / 源 MAC 顺手刷新 ARP 表。

### 7.3 IPv4

[`src/net/net/ipv4.h`](/Users/liushiming/CLionProjects/tiny-net/src/net/net/ipv4.h) / [`src/net/src/ipv4.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/ipv4.c)

IPv4 模块负责：

- 路由选择
- IP 头校验
- 分片发送
- 分片重组
- 向上分发到 ICMP / UDP / TCP / Raw

当前参数：

| 参数 | 值 |
|---|---|
| `IPV4_FRAGS_MAX_NR` | 5 |
| `IPV4_FRAGS_BUFFER_MAX_NR` | 20 |
| `IPV4_ROUTE_TABLE_MAX_NR` | 32 |

实现现状说明：

- 发送路径支持 MTU 分片
- 接收路径支持按 `(源 IP, IP ID)` 进行分片重组
- 仅做本机接收，不做转发
- `ipv4_input()` 当前接受“与本接口网段匹配或广播”的目标地址，而不是严格只接受本机单个 IP

最后一条是源码真实行为，不是标准主机协议栈常见做法，后续如果要更贴近真实主机语义，这里还需要收紧。

### 7.4 ICMPv4

[`src/net/net/icmp_v4.h`](/Users/liushiming/CLionProjects/tiny-net/src/net/net/icmp_v4.h) / [`src/net/src/icmp_v4.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/icmp_v4.c)

当前实现支持：

- Echo Request
- Echo Reply
- Destination Unreachable

行为：

- 收到 Echo Request 时自动构造 Echo Reply
- UDP 端口不可达时，IPv4 层会回发 ICMP Port Unreachable
- 其他 ICMP 类型会转交给 Raw Socket

虽然 `icmp_v4_init()` 存在，但当前主启动路径并没有显式调用它；现有实现不依赖额外初始化状态。

### 7.5 Raw Socket

[`src/net/src/raw.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/raw.c)

Raw Socket 允许应用直接收发 IP 层负载。

当前特征：

- 最大实例数：`RAW_MAX_NR = 64`
- 有独立接收队列：`RAW_RECV_QUEUE_LEN = 128`
- 支持按协议号、本地 IP、远端 IP 匹配
- 常用于承接 ICMP 或其他未被显式支持的 IP 协议

### 7.6 UDP

[`src/net/net/udp.h`](/Users/liushiming/CLionProjects/tiny-net/src/net/net/udp.h) / [`src/net/src/udp.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/udp.c)

当前能力：

- 最大 UDP socket 数：`UDP_MAX_NR = 64`
- 动态端口范围：`49152 - 65535`
- 接收队列长度：`UDP_RECV_QUEUE_LEN = 128`
- 发送时计算 UDP 伪首部校验和
- 支持 `bind` / `connect` / `sendto` / `recvfrom`

当前实现里有一个值得保留的细节：

- `udp_find()` 在对端端口匹配但对端 IP 不匹配时，允许做一次“弱匹配”
- 这是为了兼容实验环境里网关 / NAT 改写源 IP、甚至校验和未同步更新的情况

这不是通用协议栈的标准行为，但对本仓库当前联调环境是有帮助的。

## 10. 回环接口

[`src/net/src/loop.c`](/Users/liushiming/CLionProjects/tiny-net/src/net/src/loop.c)

`loop_init()` 会创建一个 `loop` 接口，并配置：

- Netmask：`255.0.0.0`

回环实现很直接：

- 包先进入 `out_q`

- 直接塞回 `in_q`

## 11. 收包路径

### 11.1 外部网卡收包

```text
pcap recv_thread
  -> pktbuf_alloc + pktbuf_write
  -> netif_put_in()
  -> exmsg_netif_in()
  -> exmsg 工作线程
  -> netif->link_layer->input()
  -> ether_input()
      -> arp_in() / ipv4_input()
```

### 11.2 IPv4 向上传递

```text
ipv4_input()
  -> 校验头部
  -> 必要时重组分片
  -> 按 protocol 分发
     -> ICMP: icmp_v4_input()
     -> UDP:  udp_input()
     -> TCP:  tcp_input()
     -> 其他: raw_input()
```

### 11.3 应用线程收数据

```text
x_recv / x_recvfrom / x_accept
  -> exmsg_func_exec()
  -> 协议模块尝试取数据
  -> 没数据则挂到 sock_wait
  -> 收包到达后由 sock_wakeup() 唤醒
```

## 12. 发包路径

```text
应用线程
  -> x_send / x_sendto / x_connect
  -> exmsg_func_exec()
  -> TCP / UDP / RAW 生成传输层数据
  -> ipv4_output()
      -> 查路由
      -> 必要时分片
      -> netif_out()
          -> 以太网接口: ether_output()
              -> ARP 命中则直接封装 MAC
              -> ARP 未命中则缓存包并发 ARP 请求
          -> loopback: 直接进本地输入队列
  -> netif->out_q
  -> pcap send_thread
  -> pcap_inject()
```

## 13. 线程模型与并发策略

当前线程模型很清楚：

- 主线程：调用 `tiny_net_init()`，通常随后进入循环等待
- `exmsg` 工作线程：串行处理协议栈核心逻辑
- `pcap recv_thread`：抓包
- `pcap send_thread`：发包

并发策略不是“所有模块自己加锁”，而是：

- 协议状态尽量集中在 `exmsg` 线程串行修改
- 队列边界用 `fixq` + 信号量隔离线程
- FD 表和 `epoll` 结构用互斥锁保护

这让实现简单很多，但也意味着：

- 协议栈吞吐受单个工作线程上限影响
- 任一长耗时逻辑都可能阻塞整个协议处理通路

## 15. 当前局限与注意事项

基于当前代码，下面这些点需要明确：

1. `tiny_net_init()` 才是实际入口  
   `net_init()/net_start()` 还没有接管完整启动流程。

2. IPv4 还不是严格的“主机协议栈接收语义”  
   目前按网段匹配目标地址，后续应收紧为“本机地址 + 广播 + 必要的本地回环”。

3. 不支持 IP 转发  
   路由表仅用于本机出站查路由，不是转发平面。

4. DNS 是最小实现  
   只处理 IPv4 A 记录，默认 DNS 服务器硬编码为 `8.8.8.8`。

5. 资源上限固定  
   socket、route、ARP、pktbuf 都受编译期常量约束。

6. `SO_REUSEADDR` 目前只是兼容占位  
   还不是完整 BSD 语义。

7. 实验环境色彩较强  
   包括虚拟 IP 生成规则、UDP 弱匹配、默认 DNS 服务器等。
